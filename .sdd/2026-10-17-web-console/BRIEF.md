# 網頁操作台 — Requirements Brief

## Goal
標的資訊面分析服務目前只能以程式呼叫。本功能提供一個網頁操作台，讓使用者在瀏覽器裡完成服務提供的每一件事：申請與管理自己的 API key、搜尋標的新聞、發起分析並等到結果出來、查看追蹤標的的當日評等、查看評等回測的命中率。畫面只呈現服務已有的資訊與能力，不新增任何業務規則；所有判斷（評等、命中與否、能不能用）都以服務的回答為準。

## Requirements

### 共通
- 操作台全部以繁體中文呈現；評等、市場類別、交易時段、狀態等一律顯示中文名稱（強烈看多 / 看多 / 中性 / 看空 / 強烈看空；加密貨幣 / 台股 / 美股；盤前 / 盤中 / 盤後）。
- 評等以一致的語氣色呈現：看多類為正向、看空類為負向、中性為中立，全操作台同一套。
- 服務拒絕或失敗時，畫面顯示服務給的原因，不顯示看不懂的錯誤代碼；服務整個連不上時，顯示「服務暫時無法使用」並可重試。
- 操作台隨時顯示服務是否連得上。

### API key
- 使用者可以在操作台申請新的 API key（填名稱）。申請成功時完整 API key 只出現這一次，畫面要明確提醒「請立即保存」並提供複製。
- 申請成功後，這把 API key 自動成為這個瀏覽器目前使用的 API key。
- 使用者也可以貼上一把既有的 API key 來使用；貼上後立即向服務確認它的狀態。
- 瀏覽器會記住目前使用的 API key，下次打開不必重貼；畫面上只顯示 API key 名稱與部分遮蔽的字串，不完整顯示。
- 使用者可以「在這個瀏覽器忘記」API key（不影響 API key 本身），也可以「撤銷」API key（永久失效）。撤銷前必須二次確認，並說明撤銷不可回復。
- API key 狀態「停用中」時，畫面說明需等 administrator 啟用，並可重新檢查狀態。
- 需要 API key 的功能（新聞、分析、追蹤標的評等、回測）在沒有可用 API key 時，不讓使用者操作，改為引導到 API key 設定。

### 新聞搜尋
- 使用者選市場類別、輸入標的，即可搜尋近 7 天新聞；結果新到舊，每則顯示標題（可開啟原文）、新聞來源、發布時間、摘要（有才顯示）。
- 部分新聞來源失敗時，結果照常顯示，另外提示哪些來源這次沒取到。
- 沒有任何新聞時，明確顯示「近 7 天沒有新聞」，而不是空白。

### 標的分析
- 使用者選市場類別、輸入標的，即可發起分析。
- 服務說這是一筆新的分析時，畫面顯示「分析中」並自動定時更新，直到完成或失敗；服務直接回覆可重用的既有分析時，照樣顯示該分析（已完成就直接顯示結果，仍在分析中就繼續等）。
- 分析完成時顯示：評等、信心指數、時間範圍、分析理由、關鍵事件（可開啟來源）、風險因子、分析時價格（含幣別、價格來源與時間；未取得時顯示「未取得」）、分析佐證新聞清單。
- 分析失敗時顯示失敗原因，並可重新發起。
- 每一筆分析有自己的網址，可以直接打開查看。
- 瀏覽器記住這裡發起過的分析（最近 20 筆），使用者可以從清單回到任何一筆。

### 追蹤標的評等
- 顯示所有仍在追蹤中的標的最新一天的綜合評等：標的、市場類別、交易日、綜合評等、綜合分數、信心指數、更新時間。
- 可展開某一標的，看當天各交易時段（盤前 / 盤中 / 盤後）的評等、信心、理由、關鍵事件、風險因子；還沒產生的時段顯示「尚未產生」。
- 可指定只看某一個標的（標的與市場類別一起指定）。
- 沒有任何追蹤標的評等時，明確說明目前沒有資料。

### 評等回測
- 可選擇分析完成的期間（起日、迄日，可只填一邊或都不填）與單一標的（標的與市場類別一起指定，或都不指定）來查詢。
- 顯示命中率總表：整體命中率並列隨機猜測 50% 作比較，以及依市場類別、評等、信心分組（低 / 中 / 高）的命中率與命中、沒命中筆數。
- 命中率「沒有資料」時顯示「沒有資料」，不顯示 0%。
- 顯示各回測結果的筆數（命中 / 沒命中 / 中性 / 尚未到期 / 無法評估）與中性評等的平均漲跌幅。
- 顯示逐筆明細：標的、評等、信心、時間範圍、完成時間、起點價格、檢查日、檢查點價格、漲跌幅、回測結果；可點回該筆分析。

Each example lists **only** the data that affects the behavior — nothing more.

### Rule: 需要 API key 的功能依 API key 狀況決定能不能用
| # | Given (only relevant data) | When | Then |

## Out of Scope
- 啟用 / 停用 API key（administrator 仍直接修改資料）。
- 新增、暫停追蹤標的，或查看時段執行紀錄（服務沒有提供）。
- 列出所有人發起過的分析（服務沒有提供，只記住本瀏覽器發起的）。
- 帳號登入、多使用者、權限。
- 價格走勢圖、K 線等任何技術面呈現。
- 手機 App；操作台以網頁呈現，手機瀏覽器需可正常閱讀與操作。

## Open Decisions
Items the PRD author should resolve:
- 分析等候時自動更新的頻率，以及等候多久後停止自動更新、改為讓使用者手動重新整理。
- 「記住 API key」與「我發起過的分析」只存在這個瀏覽器；換瀏覽器就不見，PRD 確認接受。
- 回測查詢預設期間（建議預設不限期間，與服務一致）。

## Context / Background
- 使用者要求依 clarify → prd → architecture → implement (code-first) → improve-codebase → contract 流程全自動進行。Jev 評估規模為 large（1.00），建議階段與上述流程一致，採用之。
- 使用者指示自動進行，本 brief 的開放問題由 Claude 依服務既有規格決定，未逐一詢問：介面語言採繁體中文（服務訊息皆為繁體中文）；API key 存於瀏覽器並可「忘記」；分析清單只記住本瀏覽器發起的最近 20 筆（服務沒有列出分析的能力，否則使用者無法回到之前的分析）；畫面設計參考 Mobbin 上的同類產品介面。
- 所有業務規則沿用服務端既有規格（API key 管理、新聞搜尋、標的分析、分析時價格、上櫃股票、追蹤標的時段評等、分析評等回測）；操作台不重新判斷任何規則，只呈現服務的回答。
- 錯誤原因文字以服務回覆為準（例：「找不到此標的」「目前分析數量已達上限，請稍後再試」「期間不正確」）。
