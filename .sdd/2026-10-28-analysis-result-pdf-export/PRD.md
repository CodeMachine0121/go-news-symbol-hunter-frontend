# Product Requirements Document (PRD) — 分析結果匯出 PDF

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering, Design

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 分析事件頁可以看到完整的分析結果，但無法留存或轉給別人。截圖會切成好幾張、新聞來源點不開，複製貼上也會失去版面。
- **Expected Outcome:**
  - 已完成的分析可以在兩個動作內（按「匯出 PDF」、在存檔視窗按儲存）存成一份 PDF。
  - PDF 的內容與分析事件頁顯示的分析結果完全一致（評等、信心指數、分析時價格到服務給的每一位數、每一則關鍵事件、風險因子與佐證新聞）。
  - PDF 以 A4 直式呈現，黑白列印仍可辨讀；佐證新聞印成紙本也查得到來源。
- **Out of Scope:**
  - 不經過存檔視窗、直接下載檔案的方式。
  - 從「我發起過的分析」或其他頁面匯出；一次匯出多筆。
  - 匯出分析中、分析失敗的分析事件。
  - 匯出新聞搜尋、追蹤標的評等、評等回測。
  - 圖表、走勢圖或任何服務未提供的資訊。
  - 由服務產生或保存 PDF。

---

## 2. User Personas

- **Primary Role(s):** 持有已啟用 API key 的使用者（專案擁有者本人為主要使用者）。
- **Usage Context:** 桌機瀏覽器為主；看完一筆分析後存檔留底，或轉給別人參考。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 只有已完成且有分析結果的分析可以匯出 [priority: P0]
**As a** 使用者, **I want** 只在分析已完成時看到「匯出 PDF」, **so that** 我不會匯出一份不完整或失敗的報告。

```gherkin
Scenario: 已完成的分析顯示匯出動作
  Given 分析事件狀態為「已完成」且有分析結果
  When 使用者打開該分析事件頁
  Then 頁首動作區出現「匯出 PDF」

Scenario: 分析中不顯示匯出動作
  Given 分析事件狀態為「分析中」
  When 使用者打開該分析事件頁
  Then 頁首動作區沒有「匯出 PDF」

Scenario: 分析失敗不顯示匯出動作
  Given 分析事件狀態為「失敗」
  When 使用者打開該分析事件頁
  Then 頁首動作區沒有「匯出 PDF」

Scenario: 分析完成時匯出動作隨即出現
  Given 使用者停在狀態為「分析中」的分析事件頁
  When 自動更新取得狀態「已完成」與分析結果
  Then 頁首動作區出現「匯出 PDF」，不必重新整理頁面
```

### US-02 — 匯出成 PDF [priority: P0]
**As a** 使用者, **I want** 按一下就打開一份排好版的分析報告並存成 PDF, **so that** 我可以留存或轉給別人。

```gherkin
Scenario: 匯出開啟分析報告並開啟存檔視窗
  Given 分析事件 #42 狀態為「已完成」
  When 使用者在分析事件頁按「匯出 PDF」
  Then 在新分頁打開分析事件 #42 的分析報告
  And 分析報告顯示完成後，自動開啟存檔視窗
  And 原本的分析事件頁維持不變

Scenario: 取消存檔視窗後可以再次匯出
  Given 使用者停在分析事件 #42 的分析報告，存檔視窗已開啟
  When 使用者取消存檔視窗
  Then 停留在分析報告
  And 報告上方提供「匯出 PDF」可再次開啟存檔視窗，以及「返回分析事件」回到分析事件 #42

Scenario: 直接打開分析報告的網址
  Given 分析事件 #42 狀態為「已完成」
  When 使用者直接打開分析事件 #42 的分析報告網址
  Then 顯示分析事件 #42 的分析報告
  And 自動開啟存檔視窗

Scenario: 直接打開尚無分析結果的分析報告
  Given 分析事件 #43 狀態為「分析中」或「失敗」
  When 使用者直接打開分析事件 #43 的分析報告網址
  Then 顯示「這筆分析尚無可匯出的結果」並提供「返回分析事件」
  And 不開啟存檔視窗

Scenario: 沒有可用的 API key 時打開分析報告
  Given 這個瀏覽器沒有可用的 API key
  When 使用者打開任何一份分析報告
  Then 依操作台既有的 API key 引導顯示（尚未設定、停用中或無效）
  And 不開啟存檔視窗

Scenario: 服務無法回覆時打開分析報告
  Given 服務暫時無法使用
  When 使用者打開分析事件 #42 的分析報告
  Then 顯示「服務暫時無法使用」並可重試
  And 不開啟存檔視窗
```

### US-03 — 預設檔名可辨識 [priority: P0]
**As a** 使用者, **I want** PDF 預設檔名就能看出是哪個標的、哪一天的分析, **so that** 我不必每次手動改名。

```gherkin
Scenario: 台股的預設檔名
  Given 分析事件的市場類別為台股、標的為 2330、分析完成於台灣時間 2026-10-28
  When 存檔視窗開啟
  Then 預設檔名為「台股-2330-分析-2026-10-28」

Scenario: 美股的預設檔名
  Given 分析事件的市場類別為美股、標的為 AAPL、分析完成於台灣時間 2026-10-27
  When 存檔視窗開啟
  Then 預設檔名為「美股-AAPL-分析-2026-10-27」

Scenario: 分析完成日期以台灣時間計
  Given 分析事件的市場類別為加密貨幣、標的為 BTC、分析完成於台灣時間 2026-10-28 23:59
  When 存檔視窗開啟
  Then 預設檔名為「加密貨幣-BTC-分析-2026-10-28」
```

### US-04 — 報告內容完整且清楚 [priority: P0]
**As a** 使用者, **I want** 報告依固定順序呈現頁首、分析結論、關鍵事件、風險因子、分析佐證與頁尾, **so that** 任何人拿到都能快速讀懂這次分析。

```gherkin
Scenario: 報告頁首
  Given 分析事件 #42 的市場類別為台股、標的為 2330、分析完成於台灣時間 2026-10-28 09:15
  When 使用者打開分析報告
  Then 頁首顯示「標的分析報告」、「台股」、「2330」、「分析事件 #42」與分析完成時間「2026-10-28 09:15」

Scenario: 分析結論
  Given 分析結果的評等為看多、時間範圍為短期、信心指數 72、分析時價格 1050.5 TWD
  When 使用者打開分析報告
  Then 分析結論顯示評等「看多」、時間範圍「短期（兩週內）」、信心指數「72」與分析時價格「1050.5 TWD」，並附價格來源與取得時間
  And 分析理由依原本的分段呈現

Scenario: 分析時價格未取得
  Given 分析結果沒有分析時價格
  When 使用者打開分析報告
  Then 分析時價格顯示「未取得」

Scenario: 逐條列出關鍵事件與風險因子
  Given 分析結果有 3 個關鍵事件與 2 個風險因子
  When 使用者打開分析報告
  Then 關鍵事件區塊逐條列出 3 個關鍵事件
  And 風險因子區塊逐條列出 2 個風險因子

Scenario: 沒有關鍵事件
  Given 分析結果沒有關鍵事件
  When 使用者打開分析報告
  Then 關鍵事件區塊保留，並顯示「沒有關鍵事件」

Scenario: 沒有風險因子
  Given 分析結果沒有風險因子
  When 使用者打開分析報告
  Then 風險因子區塊保留，並顯示「沒有風險因子」

Scenario: 分析佐證附完整網址
  Given 分析結果參考了 12 則新聞
  When 使用者打開分析報告
  Then 分析佐證區塊標示「本次分析參考的 12 則新聞」
  And 12 則新聞都列出標題、新聞來源、發布時間，並在標題下方印出完整的新聞網址
  And 每則新聞的標題可以點擊開啟原文

Scenario: 報告頁尾
  Given 使用者於台灣時間 2026-10-28 10:30 打開分析報告
  When 存成 PDF
  Then 頁尾顯示「匯出時間 2026-10-28 10:30」與「本報告僅供資訊參考，不構成任何投資建議」
```

### US-05 — 版面適合紙本 [priority: P1]
**As a** 使用者, **I want** PDF 版面為紙本排版, **so that** 列印或在螢幕上閱讀都清楚。

```gherkin
Scenario: 黑白列印仍可辨識評等
  Given 分析結果的評等為強烈看空
  When 以黑白列印分析報告
  Then 仍可讀到「強烈看空」四個字

Scenario: 內容超過一頁時延續到下一頁
  Given 分析佐證的新聞多到超過一頁
  When 存成 PDF
  Then 內容延續到第二頁，每一則佐證新聞完整留在同一頁
  And 每一個關鍵事件完整留在同一頁
  And 區塊標題不會單獨留在頁底

Scenario: PDF 不含操作元件
  Given 任何一份可匯出的分析報告
  When 存成 PDF
  Then PDF 中沒有操作台的選單、「匯出 PDF」、「返回分析事件」或任何按鈕
  And PDF 為 A4 直式
```

## 4. Business Flow & Logic

- **Flow:**
  ```
  分析事件頁（狀態：已完成）
    └─ 按「匯出 PDF」
        └─ 新分頁打開「分析報告」（每份報告有自己的網址，可直接打開）
            ├─ 取得分析事件 → 已完成且有分析結果 → 顯示報告 → 自動開啟存檔視窗
            │     ├─ 使用者儲存 → 得到 PDF
            │     └─ 使用者取消 → 停留在報告，可再按「匯出 PDF」或「返回分析事件」
            ├─ 取得分析事件 → 分析中 / 失敗 → 「這筆分析尚無可匯出的結果」
            └─ 沒有可用 API key / 服務無法回覆 → 沿用操作台既有的引導與錯誤畫面
  ```
- **Core Business Rules:**
  - **可匯出條件：** 分析事件狀態為「已完成」且有分析結果。其餘狀態一律不可匯出。
  - **預設檔名：** 「{市場類別中文名稱}-{標的}-分析-{分析完成日期}」，分析完成日期以台灣時間的年-月-日表示。
  - **報告內容：** 與分析事件頁顯示的分析結果同一份資料、同樣的中文名稱與數值，不另做任何計算或判斷。
  - **匯出時間：** 打開分析報告當下的台灣時間，精確到分鐘。
  - **存檔視窗只開一次：** 報告顯示完成後自動開啟一次；之後只在使用者按「匯出 PDF」時再開啟。
- **Edge Cases:**
  - 使用者取消存檔視窗：停留在報告，可再次匯出。
  - 分析報告在分析中時被直接打開：不等待、不自動更新，顯示尚無可匯出的結果。
  - 服務無法回覆或 API key 不可用：沿用操作台既有畫面，不開啟存檔視窗。
  - 分析事件不存在：沿用操作台既有的「服務拒絕」畫面顯示服務給的原因。

## 5. UI/UX Design & Interaction

- **Prototype Link:** N/A（沿用操作台既有版面元素與語氣色）。
- **Key Interactions:**
  - 分析事件頁：「匯出 PDF」與「返回標的分析」並列於頁首動作區。
  - 分析報告（螢幕上）：報告上方有「匯出 PDF」與「返回分析事件」；下方為紙張寬度的報告本體。
  - 分析報告（PDF）：只有報告本體，A4 直式；評等以語氣色加中文名稱呈現。
- **Loading state:** 取得分析事件期間顯示載入中，不開啟存檔視窗。
- **Empty state:** 關鍵事件、風險因子為空時，區塊保留並顯示「沒有關鍵事件」／「沒有風險因子」。
- **Error state:** 沿用操作台既有錯誤畫面；尚無分析結果時顯示「這筆分析尚無可匯出的結果」。

## 6. Non-Functional Requirements

- **Performance:** 分析報告在取得分析事件後立即呈現；存檔視窗在報告呈現完成後才開啟，不出現空白或不完整的 PDF。
- **Security:** 分析報告與其他受保護功能一樣，需要已啟用的 API key 才能取得內容。
- **Compatibility:** 桌機版 Chrome、Edge、Safari、Firefox 的最新版本，皆可透過存檔視窗存成 PDF。
- **Fidelity:** PDF 內的文字可選取、可複製，新聞連結可點擊。
- **Analytics / Tracking:** N/A。

---

## 7. Dependencies & Risks

- **External Dependencies:** 無新增；沿用既有的取得分析事件能力。
- **Known Risks:**
  - 各瀏覽器存檔視窗的預設選項不同（有的預設為印表機），使用者可能需要手動選「另存為 PDF」。
  - 各瀏覽器可能在 PDF 加上自己的頁首頁尾（網址、日期），使用者可在存檔視窗關閉；報告本身的頁首頁尾不受影響。
